🧠 Fundamentos del Análisis Léxico vs. Sintáctico
① ¿Qué es un Error Léxico? (Definición Formal)
Un error léxico es una anomalía detectada durante la primera fase de compilación en la que el analizador léxico (scanner) encuentra una subsecuencia de caracteres del código fuente que no coincide con ninguna expresión regular ni patrón formal definido en el alfabeto $\Sigma$ del lenguaje objetivo.
Definición Teórica Formal:
Sea Σ el alfabeto admisible del lenguaje L. Un lexema w ∈ Σ* constituye un error léxico si y solo si:
∀ Token T ∈ Tokens(L), w ∉ L(ExpresiónRegular(T)).
Manifestaciones típicas: Símbolos ajenos al alfabeto (ej. $, ~, `), identificadores que inician con dígitos (ej. 99variable), números decimales con múltiples puntos (ej. 3.14.15), o cadenas literales no cerradas antes del fin de línea.
② Análisis del Caso '@' como Error Léxico
El símbolo @ exhibe comportamientos léxicos radicalmente distintos según el lenguaje seleccionado:
  • En Python 🐍: @ de forma aislada o dentro de una expresión de variables no pertenece al alfabeto de operadores estándar ni identificadores, siendo clasificado inmediatamente como ERROR LÉXICO.
  • En Kotlin 💜: Se utiliza exclusivamente para anotaciones (ej. @JvmStatic). Cuando se intenta usar en la declaración de una variable como val @nombre = "Kotlin", el símbolo @ es inválido para el nombre del identificador y es marcado como ERROR LÉXICO.
  • En C# 🔷: Funciona como el prefijo especial Verbatim Identifier. Si va inmediatamente seguido de una palabra reservada o identificador (ej. @class, @variable), es un token VÁLIDO. Sin embargo, si aparece de forma aislada (ej. @ solo), el autómata no encuentra transición válida y emite un ERROR LÉXICO.
③ Análisis Exhaustivo del Caso "20+*5": ¿Léxico o Sintáctico?
La secuencia 20+*5 NO CONTIENE ABSOLUTAMENTE NINGÚN ERROR LÉXICO.

El analizador léxico escanea el flujo de caracteres de izquierda a derecha reconociendo tokens atómicos de forma independiente:

1. '20' → NUMERO_ENTERO ✓ [Válido: satisface /^[0-9]+$/]
2. '+' → OPERADOR_ARITMETICO ✓ [Válido: pertenece al conjunto de operadores]
3. '*' → OPERADOR_ARITMETICO ✓ [Válido: pertenece al conjunto de operadores]
4. '5' → NUMERO_ENTERO ✓ [Válido: satisface /^[0-9]+$/]
¿Por qué falla el código entonces?
El error es ESTRICTAMENTE SINTÁCTICO. El analizador sintáctico (Parser) aplica las reglas de la Gramática Libre de Contexto (GLC) $E \to E + E \mid E * E \mid \text{num}$. Dicha gramática exige obligatoriamente un operando intermedio entre dos operadores binarios. La presencia de + * contiguos viola la regla sintáctica de precedencia y formación de árboles de derivación, pero a nivel léxico, la tasa de aprobación de tokens es 100%.
④ Autómatas Finitos Deterministas (DFA) y Expresiones Regulares
El análisis léxico se fundamenta en la equivalencia formal entre Expresiones Regulares (ER) y Autómatas Finitos Deterministas (DFA):
M = (Q, Σ, δ, q0, F)
- Q: Conjunto finito de estados del scanner.
- Σ: Alfabeto de caracteres de entrada.
- δ: Función de transición δ: Q × Σ → Q.
- q0: Estado inicial de lectura.
- F: Conjunto de estados de aceptación (identificador, entero, operador, etc.).
Se implementa la regla de Máxima Coincidencia (Longest Match / Maximal Munch): el DFA consume la mayor cantidad continua de caracteres que continúen satisfaciendo un estado de aceptación antes de emitir el token y retornar al estado $q_0$.
⑤ Metodología de Comprobación y Pruebas Unitarias
Para garantizar la fiabilidad del compilador ante errores léxicos, se emplean tres pilares metodológicos:
  • Modo Pánico (Panic Mode): Al encontrar un carácter no reconocible, el scanner emite el error léxico con sus coordenadas exactas (Línea y Columna) y avanza un carácter, permitiendo diagnosticar la totalidad de errores del archivo en una sola pasada.
  • Batería de Pruebas Unitarias: Validación automática de casos límite: identificadores con prefijos numéricos (99var), números con múltiples separadores (3.14.15), y cadenas no terminadas antes del salto de línea.
  • Aislamiento de Fases: Comprobación de que expresiones sintácticamente inválidas como 20+*5 son aprobadas con 0 errores por el scanner, validando la frontera teórica entre el analizador léxico y el parser sintáctico.
